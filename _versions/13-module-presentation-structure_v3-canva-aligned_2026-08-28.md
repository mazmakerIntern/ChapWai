# หน้า 2 — วัตถุประสงค์

**หัวเรื่อง:** `Objective` · **คำโปรย:** ทำไมต้องมีระบบนี้

### ปัญหาวันนี้

| | |
|---|---|
| 📥 | ลูกค้าส่งใบเสร็จให้สำนักงานบัญชี**ทางไลน์อยู่แล้ว** — เป็นพฤติกรรมที่เกิดขึ้นเองโดยไม่มีใครสอน |
| ⌨️ | แต่ปลายทางยัง**คีย์มือทุกใบ** และต้องไล่ตรวจซ้ำทุกใบ เพราะไม่รู้ว่าใบไหนน่าสงสัย |
| 🔀 | เครื่องมืออ่านใบเสร็จที่มีในตลาด**บังคับให้ออกจากไลน์**ไปเปิดเว็บหรือแอปอื่น — ขั้นตอนที่เพิ่มมาคือเหตุผลที่คนไม่ใช้ |

### สิ่งที่ระบบนี้ทำ

> **รับเอกสารตรงจากไลน์ที่ลูกค้าใช้อยู่แล้ว อ่านข้อมูลให้อัตโนมัติ
> แล้วบอกให้ชัดว่า "ใบไหนผ่านได้เลย ใบไหนต้องตรวจ"
> พร้อมช่วยเจ้าของกิจการมอบหมายและติดตามงานในกลุ่มเดียวกันนั้น**

### วัดผลด้วยอะไร

| ✅ ตัววัดที่ใช้ | ❌ ตัววัดที่ไม่ใช้ |
|---|---|
| **เวลาที่ประหยัดได้ต่อใบ** | ความแม่นเป็นเปอร์เซ็นต์ |
| **จำนวนใบที่ผ่านได้เลย ไม่ต้องแตะ** | จำนวนฟีเจอร์ |

> เป้าหมายที่สื่อสารกับลูกค้า: **"จาก 100 ใบ ตรวจแค่ 15 ใบ อีก 85 ใบผ่านได้เลย"**

### 3 หลักการที่ยึดตลอดโครงการ

| | |
|---|---|
| **1 · จบในไลน์** | ทุกอย่างที่ลูกค้าต้องทำ ต้องจบในไลน์ — ถ้าเจอขั้นตอนที่ต้องเปิดเว็บข้างนอก แปลว่าออกแบบผิด |
| **2 · ไม่กั้น แต่ให้เห็น** | บันทึกทุกใบ แล้วติดธงใบที่น่าสงสัย · เปิดสิทธิ์ให้ใช้งานสะดวก แต่แสดงเสมอว่าใครทำอะไร — แทนการตั้งกำแพง |
| **3 · ข้อมูลของลูกค้าอยู่ที่ลูกค้า** | ไฟล์ปลายทางอยู่ใน Google Drive ของลูกค้าเอง ไม่รวมศูนย์ที่เรา |

# หน้า 3 — Proposed Solution

**คำโปรย:** 8 เครื่องมือหลัก สำหรับระบบ CFO ONDEMAND — พัฒนาพร้อมกันทั้งชุด

| # | โมดูล | คำอธิบาย | ทำอะไรได้ |
|---|---|---|---|
| 1 | **LINE INTAKE** | รับเอกสารผ่านไลน์ | รับทันทีที่ส่ง · ส่งทีละหลายใบได้ · เมนูปุ่มในแชท · กันเอกสารซ้ำ |
| 2 | **OCR & EXTRACTION** | อ่านข้อมูลจากเอกสาร | อ่านใบเสร็จเป็นข้อมูล · ตรวจตัวเลขอัตโนมัติ · บอกระดับความมั่นใจ · ติดธงใบที่ควรตรวจ |
| 3 | **DOCUMENT STORAGE** | จัดเก็บและจัดระเบียบไฟล์ | เก็บครบทุกใบ · ส่งต่อเข้า Drive ของลูกค้า · จัดโฟลเดอร์และตั้งชื่อให้ · เตือนก่อนพื้นที่เต็ม |
| 4 | **REVIEW & CORRECTION** | ตรวจและแก้ไขข้อมูล | ตรวจเฉพาะใบที่ควรตรวจ · การ์ดตรวจในแชท · แก้ช่องไหนก็ได้ · ยิ่งใช้ยิ่งแม่น |
| 5 | **EXPORT & REPORT** | ส่งออกไฟล์ Excel / PDF | รายงาน 2 ชีต · PDF ตรวจรายใบ · ภาษาไทยไม่เพี้ยน · ส่งเฉพาะคนที่มีสิทธิ์ |
| 6 | **PERMISSION & USER** | จัดการสิทธิ์การเข้าถึง | สิทธิ์ระดับทีม / ระดับเจ้าของ · เจ้าของตั้งเองได้ · ประวัติการใช้งาน · รองรับแบรนด์พาร์ทเนอร์ |
| 7 | **TASK TRACKER** | เลขาเสมือนในไลน์กลุ่ม | มอบหมายงาน · เตือนแบบมีจังหวะ · สรุปวันละครั้ง · ปิดงานอัตโนมัติ |
| 8 | **CONSOLE & DASHBOARD** | หน้าเว็บหลังบ้าน | Documents Tab · Tasks Tab · Quick Stats · Export Center |

> **บนหน้า:** ทั้ง 8 โมดูลใช้ระบบรับข้อความ · ระบบสิทธิ์ · ระบบแจ้งเตือน · หน้าเว็บหลังบ้าน **ชุดเดียวกัน** จึงพัฒนาพร้อมกันครั้งเดียว ไม่ต้องกลับมาสร้างซ้ำ

## หน้า 5 — LINE INTAKE (Module Overview)

**Platform Types**
- ไลน์ทางการของระบบ — **หน้าตาเหมือนกันทั้งแชทส่วนตัวและแชทกลุ่ม**
- ใช้ปุ่มในแชทเป็นหลัก กดได้ทุกห้อง
- **ไม่มีเมนูภาพค้างจอ** — เพราะแสดงได้เฉพาะแชทส่วนตัว และต้องทำรูปใหม่ทุกครั้งที่เพิ่มฟีเจอร์ ยิ่งมีพาร์ทเนอร์หลายแบรนด์ยิ่งต้องทำหลายชุด
- ต่างกันจุดเดียว: **ในกลุ่มต้องเรียกชื่อบอทก่อน** (`ฉับไว`) ส่วนแชทส่วนตัวพิมพ์อะไรก็ตอบ

**User Permissions**

| บทบาท | ทำอะไรได้ในโมดูลนี้ |
|---|---|
| **พนักงานในกลุ่ม** | ส่งเอกสาร · สั่งให้อ่านข้อมูล · ดูว่าไฟล์เข้าระบบแล้วหรือยัง · ตั้งค่าของตัวเอง |
| **เจ้าของกิจการ** | ทุกข้อข้างบน + ผูกกลุ่มกับบริษัท · ตั้งค่าระดับบริษัท |

**User Capabilities**
- ส่งรูปหรือไฟล์เข้าไลน์ได้ทันที ไม่ต้องออกจากแอป
- มีปุ่มเปิดกล้องถ่ายใบเสร็จได้เลย จาก 3 ขั้นตอนเหลือขั้นตอนเดียว
- พิมพ์ `ฉับไว` เฉย ๆ ก็ได้เมนูปุ่มขึ้นมาให้เลือก
- เลือกได้ว่าจะให้ "อ่านข้อมูล + เก็บไฟล์" หรือ "เก็บไฟล์เฉย ๆ" และให้ระบบจำไว้

**Core Functions**

| ฟังก์ชัน | คำอธิบาย |
|---|---|
| **Instant Receive** | รับเอกสารทันทีที่ส่งเข้ามา |
| **Safe Capture** | เก็บไฟล์ไว้ก่อนที่ไลน์จะลบ |
| **Batch Upload** | ส่งทีละหลายใบ ถามครั้งเดียว |
| **Smart Command** | เรียกใช้ด้วยคำพูดธรรมดา |
| **Button Menu** | เมนูปุ่มในแชท ใช้ได้ทุกห้อง |
| **Remember My Choice** | จำค่าที่ตั้งไว้ ไม่ต้องตอบซ้ำ |
| **Duplicate Check** | กันเอกสารที่ส่งซ้ำ |
| **Auto Fix Image** | ปรับภาพให้พร้อมอ่าน |
| **Team Directory** | ทะเบียนสมาชิกในกลุ่ม |

**NOTIFICATION**
- ได้รับ 12 รูปแล้ว — ดูเหมือนใบกำกับภาษี
- กำลังอ่านข้อมูลให้ครับ… `[ครั้งนี้แค่เก็บไฟล์]`
- ใบนี้เคยส่งมาแล้วเมื่อ 3 วันก่อน `[ข้าม] [บันทึกซ้ำ]`
- รับไฟล์ไม่ทัน ขอให้ส่งใหม่อีกครั้งนะครับ

## หน้า 28 — PERMISSION & USER (Module Overview)

**Platform Types**
- ผูกกลุ่มไลน์เข้ากับบริษัท — 1 กลุ่ม = 1 บริษัท
- ตั้งค่าสิทธิ์จากแชทส่วนตัวของเจ้าของ
- หน้าเว็บสำหรับสำนักงานบัญชี

**User Permissions — 5 บทบาท**

| บทบาท | ใคร | ต้อง login ไหม |
|---|---|---|
| **สมาชิกกลุ่ม** | พนักงานของ SME ที่อยู่ในกลุ่มไลน์ | ไม่ต้อง — อยู่ในกลุ่มคือสิทธิ์ |
| **เจ้าของกิจการ** | เจ้าของ SME | ยืนยันตัวตนครั้งเดียวตอนเริ่มใช้ |
| **เจ้าหน้าที่บัญชี** | พนักงานสำนักงาน ดูแลหลายบริษัท | login หน้าเว็บ |
| **ผู้ดูแลสำนักงาน** | คุณตี๋ | login หน้าเว็บ |
| **ผู้ดูแลระบบ** | ทีม MAZ / เจ้าของแบรนด์พาร์ทเนอร์ | login หน้าเว็บ |

**User Capabilities**
- ไม่ต้อง login รายคน — อยู่ในกลุ่มก็ใช้งานได้เลย
- เจ้าของเลือกเองได้ว่าจะให้ทุกคนดูยอดสรุปไหม
- ได้รับแจ้งเตือนเมื่อมีคนใหม่เข้ากลุ่ม

| ฟังก์ชัน | คำอธิบาย |

## หน้า 53 — สิ่งที่ตกลงแล้ว

| ประเด็น | ข้อสรุป |
|---|---|
| การส่งข้อมูลไปประมวลผลกับ AI | ✅ ทำได้ — ยังควรจัดทำเอกสารกำกับการใช้ข้อมูลไว้ |
| ปัญหาจริงของลูกค้า | ✅ "อ่านใบเสร็จได้บนไลน์ ไม่ต้องสลับไปเว็บอื่น" |
| ลำดับความสำคัญ | ✅ อ่านเอกสารทำก่อน · วิเคราะห์งบไว้เฟสถัดไป |
| ทีมพัฒนาและเทคโนโลยี | ✅ ทีม MAZ |
| ที่เก็บไฟล์ | ✅ Drive ของลูกค้าเอง — แต่เป็นสำเนา ไม่ใช่ที่เก็บหลัก |
| เมนูภาพค้างจอ | ✅ **ไม่ทำ** — ใช้คำเรียก `ฉับไว` + ปุ่มในแชท ใช้ได้ทุกห้อง ทุกแบรนด์ |
| หน้าจอแก้ไขเต็มรูปแบบในไลน์ | ✅ **ไม่ทำในเฟสนี้** — ใช้การ์ดในแชทแทน |
| สิทธิ์ดูเอกสาร | ✅ **ทุกคนในกลุ่มดูเอกสารของบริษัทตัวเองได้** |
| สิทธิ์ดูยอดสรุป | ✅ **เจ้าของตั้งเองได้** ค่าเริ่มต้นคือเปิด |
| เลขากลุ่มและหน้าเว็บ | ✅ **ทำพร้อมกันในเฟส 1** ไม่แยกไปทำรอบสอง |
| การขออนุมัติ | ✅ **ทำในเฟส 1** ใช้ระบบเดียวกับการมอบหมายงาน |

**หลักที่ตกลงแล้ว ไม่ต้องถกซ้ำ:**
เก็บไฟล์เสมอ · บันทึกทุกใบแล้วติดธง · ไม่ขายความแม่นเป็นพาดหัว · ไม่ผูกกับ AI เจ้าใดเจ้าหนึ่ง · ส่งออกเป็นไฟล์ก่อน · **ระบบต้องใช้งานได้แม้ AI ขัดข้อง** · **ไม่กั้น แต่ให้เห็น** · **แจ้งเตือนรวมข้อความเดียวต่อกลุ่มต่อวัน**

## หน้า 54 — สิ่งที่ยังต้องการจากคุณตี๋

**🔴 ต้องได้ก่อนเริ่มพัฒนา**
- ใครเป็นเจ้าของบัญชีและระบบต่าง ๆ (ไลน์ทางการ · Google · โดเมน)
- NA.Team จะส่งมอบของเดิมหรือไม่ · มีเงื่อนไขสัญญาอะไรผูกอยู่

**🟡 ข้อมูลที่ต้องขอ**

*เรื่องการตรวจซ้ำ (สำคัญที่สุด — กระทบการออกแบบโดยตรง)*
1. ตอนตรวจซ้ำ ตรวจอะไรบ้าง — ยอดรวมอย่างเดียว หรือลงถึงเลขผู้เสียภาษี
2. ตรวจที่ไหน — ในโปรแกรม / ใน Excel / ดูกระดาษเทียบ
3. ถ้าเจอผิด แก้ตรงไหน — **ข้อนี้สำคัญที่สุด** เพราะถ้าแก้ที่ปลายทาง ระบบจะไม่มีวันแม่นขึ้น

*เรื่องช่องว่างที่เราจะไปเติม*
4. ทุกวันนี้ที่ยังต้องคีย์เอง เป็นใบประเภทไหน (บิลเขียนมือ? ภาพเบลอ? สลิปโอน?)
5. เอกสารเข้ามาทางไหนบ้างนอกจากไลน์
6. ลูกค้าที่ส่งผ่านไลน์อยู่แล้วมีกี่ราย คิดเป็นสัดส่วนเท่าไหร่

*เรื่องข้อมูลและปริมาณ*
7. ลูกค้ากี่ราย เอกสารเดือนละกี่ใบ
8. รูปแบบวันที่ที่ต้องการในไฟล์ส่งออก
9. ต้องเก็บเอกสารกี่ปี
10. ทุกวันนี้เอกสารลูกค้าเก็บที่ไหน ใครเป็นเจ้าของ

*เรื่องขอบเขต*
11. ขอ **ใบเสร็จจริง 100–300 ใบ** (ปกปิดชื่อลูกค้าได้)
12. เงื่อนไขการส่งมอบกับ NA.Team
13. ในกลุ่มลูกค้าจริง มีรูปที่ไม่เกี่ยวกับเอกสารปนมาเยอะแค่ไหน
14. งานหรือการเตือนที่อยากให้เลขาช่วยติดตามมีอะไรบ้าง
15. อยากได้ข้อมูลงานออกไปที่ Google Sheet ด้วยไหม หรือดูจากหน้าเว็บพอ

**🟡 เรื่องที่ยังไม่สรุป:** ระยะเวลาเก็บเอกสารตามกฎหมาย · PDF หลายหน้าคิดค่าบริการอย่างไร · การจับคู่คอลัมน์ให้ตรงกับโปรแกรมบัญชีปลายทาง · ชื่อคำเรียกบอทตัวจริง (`ฉับไว` เป็นชื่อชั่วคราว)

## หน้า 55 — เรื่องที่เรารู้แล้วว่าต้องระวัง

> เรื่องพวกนี้เล็ก แต่ทำให้ไฟล์หรือระบบใช้งานไม่ได้จริง — เราเจอมาแล้วตอนทำต้นแบบและแก้ไว้แล้ว

| เรื่อง | ปัญหาที่เกิด | จัดการอย่างไร |
|---|---|---|
| ภาษาไทยใน PDF | สระและวรรณยุกต์หลุดไปลอยท้ายหน้า | เลือกฟอนต์ที่รองรับ + ใส่การตรวจอัตโนมัติทุกครั้งที่สร้างไฟล์ |
| ตัวเลขใน Excel | บวกไม่ได้ เพราะเป็นตัวหนังสือ | บันทึกเป็นตัวเลขจริงเสมอ |
| เลขผู้เสียภาษี | 0 นำหน้าหาย (0105… กลายเป็น 105…) | บังคับให้เก็บเป็นข้อความเฉพาะคอลัมน์นี้ |
| ไฟล์ CSV ภาษาไทย | เปิดใน Excel แล้วเพี้ยน | ใช้ไฟล์ Excel แทน CSV |
| รูปจาก iPhone | เปิดไม่ได้ในบางเครื่อง | แปลงให้อัตโนมัติทุกครั้ง |
| PDF หลายหน้า | ค่าอ่านเพิ่มตามจำนวนหน้า | ถามก่อน และคิดราคาให้สอดคล้อง |
| ลูกค้าส่งใบซ้ำ | เกิดบ่อยมาก | ระบบจับได้และถามก่อนบันทึก |
| ไฟล์ในไลน์มีอายุ | ถ้ารอผู้ใช้ตอบก่อนจะดึงไม่ทัน | เก็บสำเนาทันทีที่ได้รับ |
| โควตาข้อความไลน์ | ค่าใช้จ่ายบานจากการแจ้งเตือน | รวมเป็นข้อความเดียวต่อกลุ่มต่อวัน |
| Drive ลูกค้าเต็ม | เขียนไฟล์ไม่ได้ และเราแก้ให้ไม่ได้ | ตรวจพื้นที่ก่อนส่งทุกครั้ง + Drive เป็นสำเนา ไม่ใช่ที่เก็บหลัก |
| ปุ่มในกลุ่ม | ใครในกลุ่มก็กดได้ | ตรวจสิทธิ์ทุกครั้งที่มีคนกด ไม่ใช่แค่ตอนแสดงปุ่ม |
| ระบบไม่รู้จักสมาชิก | มอบหมายงานให้คนที่ไม่เคยพิมพ์ไม่ได้ | ขอให้ทุกคนทักทายหนึ่งครั้งตอนบอทเข้ากลุ่ม |
| หลายคนแก้พร้อมกัน | ข้อมูลตีกัน | ระบบจำว่าใครกำลังแก้ใบไหน และแจ้งเตือนถ้าซ้อนกัน |
| เตือนงานทุกวันไม่จบ | คนเริ่มมองข้ามทั้งสรุป | เตือนแบบมีจังหวะ เลย 7 วันหยุดตาม แล้วถามเจ้าของ |
